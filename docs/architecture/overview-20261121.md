# Architecture Overview — 2026-11-21

## 1. Goal

## 2. Main modules
- **Zero-build static SPA**: No `package.json` and no bundler; served directly as static HTML/CSS/JS.
- **Entry points**:
  - `index.html` (103 lines): loads 10 CSS files ending in `sitota-theme.css`, followed by 15 ordered classic `<script>` tags in `js/`.
  - `forge.html`: redirect shim to `index.html`.
- **Key `js/` modules** (classic global-scope scripts):
  - `combat-rules.js` & `data.js`: rules tables and reference data.
  - `engine.js` (2,290 lines): character creation, derived stats, and Mythras rules calculations.
  - `cloud.js` (2,293 lines): local-first autosave, Supabase auth/sync, campaign/GM-gift persistence, and conflict resolution.
  - `wiki` / `atlas` / `sitota`: world lore, interactive Sit'ota atlas, and setting modules.
  - `render.js` (1,443 lines): character builder and sheet UI rendering.
  - `router.js` (298 lines): client-side view/hash routing.
  - `play.js` (2,476 lines): Play Mode runtime (combat tracker, dice/rolls, GM gifts, live session state).
  - `official-sheet.js`: printable/official character sheet view.
  - `app.js` (2,525 lines): top-level application shell, event wiring, and bootstrap.
  - `practice.js` (103 lines): Practice Combat entry/integration.
- **`experiments/`**: 38-file Pits subsystem (standalone experimental arena/combat suite).
- **`tests/` & `.github/workflows/`**: automated test suites (including DB/SQL checks with `tests/db/base-schema.sql`) and CI workflows.

## 3. Saved data flow to Supabase
1. **Local-first autosave (`js/cloud.js`)**:
   - Writes immediately to `localStorage` under `mythrasForgeAutosave_v1` via `saveVerifiedLocal`.
   - Guest sessions are isolated via `MOCK_AUTH` so unauthenticated play never leaks into cloud records.
2. **Debounced push & lifecycle flushes**:
   - Changes queue a 1.5s debounced cloud push, with immediate flushes on `pagehide`, `visibilitychange`, and `online` events.
   - Per-character writes are serialized through `CHARACTER_SAVE_QUEUES`.
3. **Concurrency & GM gifts**:
   - Optimistic concurrency uses a `revision` counter per character record.
   - Incoming GM gifts are merged against `SERVER_COPIES` when safe; incompatible concurrent edits surface the `characterConflict` UI.
   - Play Mode polls for new GM gifts every 30s.
4. **Database schema & migrations**:
   - 7 incremental migrations live in `supabase/migrations/` (covering `campaign_gm_state` RLS, `SECURITY DEFINER` campaign RPCs, `profiles`, `site_admins`/`site_settings`, and `pits_fight_reports`).
   - Hosted on Supabase Free plan; campaign backups rely on manual JSON exports.

## 4. Three biggest structural risks
1. **Global-scope bundler-free monolith with implicit script load-order coupling**: all 15 classic scripts in `index.html` share global scope and depend on exact `<script>` ordering.
2. **Missing canonical baseline Supabase schema in git**: only an 82-line `tests/db/base-schema.sql` stand-in exists for the 5 pre-migration tables, compounded by Supabase Free-plan backup fragility.
3. **Split-world boundary & manual cache busting**: separation between `js/` and the 38-file `experiments/` Pits subsystem, plus manual `?v=` asset query-string stamping.
