# Atlas UX Spec — 2026-11-21

## 1. Who and why
Players and GMs opening the interactive Sit'ota Atlas at the table to orient themselves, zoom from the continent down into a nation and into a city/town street map, and read quick place context without leaving the map or accidentally altering world geometry.

## 2. Flow
1. **Landing (Level 1 — World)**: User opens the Atlas and immediately sees the full Sit'ota continent filling the viewport edge-to-edge (no dead grey margins).
2. **Nation dive (Level 2 — Nation)**: User clicks a nation (or selects it from the floating search/index) to trigger the cloud dive transition into that nation's map. The info sidebar swaps in sync with the map once the transition settles.
3. **Zoom-out return (Nation → World)**: User zooms out until reaching the nation's full-bleed fit; continuing or reaching that fit triggers the return transition back to the full Sit'ota continent.
4. **Town / city dive (Level 3 — Street Map)**: At the nation level, settlements with street maps show a clear street-map affordance. Clicking one opens its read-only procedural town map in the same native pan/zoom canvas.
5. **Breadcrumb navigation**: At any depth, the user can click any segment in the full clickable breadcrumb (`Sit'ota > Valeshar > Shamur`) to jump directly back to that level.

## 3. On screen
- **Primary canvas (100% full-bleed viewport)**: Edge-to-edge interactive map across all 3 levels (World, Nation, Town), inspired by Roshar / Runeterra interactive maps. Pan and zoom bounds are clamped so map edges never expose dead grey space.
- **Floating controls (over the canvas)**:
  - Full clickable breadcrumb (`Sit'ota > Valeshar > Shamur`).
  - Zoom/reset controls and search/index toggle.
- **Floating / collapsible info drawer (hidden or compact until a place is selected)**:
  - Shows place name, nation, settlement tier, street-map availability indicator, and lore text.
  - While Sit'ota lore is still placeholder, shows useful metadata (nation, tier, street-map availability, and `"Lore coming soon"`) instead of a bare `"No entry yet"`.
- **Town maps (read-only procedural Watabou)**:
  - Pre-exported/baked deterministic Watabou SVGs/WebPs from `atlas-data.json` rendered inside the native pan/zoom viewer.
  - No Watabou generator controls, no city regeneration buttons, no AI-generated imagery, and no iframe scroll-wheel traps.
- **Map labels & polish (Work Severity 2 fixes from `docs/atlas-live-386-387-20261120.md`)**:
  - One persistent, non-overlapping capital label (e.g., `Shamur` positioned cleanly without colliding with `Golshehr`).
  - Clear visual affordance on markers/rows indicating which settlements have street maps.
  - Synchronized sidebar and map swap during cloud dive transitions.

*(Note: All CSS, colors, fonts, and spacing remain Claude's UI calls within `sitota-theme.css` tokens.)*

## 4. States
- **Empty / initial**: Full Sit'ota continent centered and full-bleed; no place selected or compact continent summary in drawer.
- **Loading / transitioning**: Cloud dive transition plays smoothly; sidebar content updates in sync with the target level rather than flashing early or lagging behind.
- **Error (missing asset / data)**: Clear inline fallback message in the drawer with a button to return to the parent level via breadcrumb.
- **Signed out vs. signed in / Player vs. GM**: Read-only Atlas exploration works identically for signed-out guests, players, and GMs; no player or GM can edit or regenerate procedural Watabou town maps from the Atlas UI.
