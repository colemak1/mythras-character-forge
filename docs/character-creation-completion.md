## Explicit interpretation and manual handling

- A broadly offered specialised skill may supply multiple distinct specialities, each using one of the three choices; identical name/speciality is rejected. This is the user's delegated project choice, not an explicit Core statement. Printed career contexts are preserved together in a single dropdown option, with the actual speciality recorded separately. GM agrees suitability or substitutions.
- Initiative's average is rounded upward by the implementation. The creation text says average but does not explicitly settle half-points in the reviewed passage; this remains a documented rounding convention, not a newly discovered explicit rule.
- Background events, family choices, resources, relationships and Group Luck are GM-assisted. The app rolls/records supported tables and explains the shared Luck pool; it does not apply event effects or spend Group Luck automatically.
- Starting possessions are setting-dependent guidelines on pp.34–35; purchasable gear and its catalogue are subsystem3. Magic access and optional cult membership are GM decisions (pp.35–36); spell/rank mechanics stay in subsystem6. The optional cult step remains excluded from the wizard by the user's existing choice.
- No book-wide accuracy percentage follows from this matrix. Completion means the inventoried Core creation behavior and explicit manual handling meet this acceptance record; it does not mean every possible character or later gameplay interaction has been tested live.
