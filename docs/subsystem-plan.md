# Mythras Forge Core verification plan

Progress: **0/8 subsystems finished**. Numbering is stable; partial work does not count as finished. A subsystem is finished only when its applicable Core rules and exceptions are inventoried, implementation or explicit GM handling is checked against the user's uploaded Core rulebook, meaningful automated cases pass, and relevant signed-in workflows are verified on the deployed revision. Open interpretations, unsupported behavior, and exclusions must be explicit. This is not a book-wide accuracy percentage.

1. **Character creation and background** — characteristics, attributes, cultures, community, passions, careers, age, bonus skills and creation flow. In progress: source comparison and some automated/live cases; many workflow, source and edge cases remain.
2. **Skills and task resolution** — standard/professional skills, difficulty, augmentation, caps, opposed/differential and group rolls. Partial source and automated cases; live coverage incomplete.
3. **Equipment and economy** — money, starting gear, armour, weapons, encumbrance and their entries. Partial audit.
4. **Advancement, hazards and recovery** — improvement, training, fatigue, injuries, healing, ageing, poison and other hazards. Partial audit.
5. **Combat** — actions, styles, rounds, attacks, defences, effects and damage interactions. Partial audit.
6. **Magic and organizations** — all Core traditions, spells, spirits, cults, ranks and interactions. Partial audit.
7. **Creatures and GM procedures** — creature traits and statistics, GM systems and applicable optional rules. Inventory incomplete.
8. **Campaign and live integration** — campaign configuration, permissions, GM/player workflows, persistence, imports and deployment verification. Partial live evidence; incomplete.

The guided combat practice tutorial is a later feature, after the builder is verified and corrected; it is not included in the finished count. New work outside these subsystems must be identified explicitly. Detailed source and case tracking remains in `core-rule-scope.md` and linked audit files.
